# Source verification

Use when a conclusion rests on an external name, link, version, quote or number.

## What a source proves

- A link that opens, a package that exists or a name that matches proves only that the thing exists. It does not prove the source says what you cite, or that it is the right one. Compare title, owner or author, and version or date with your claim before calling it verified.
- Mark each claim **verified** (the cited text says it, checked in this pass), **unverified** (not checked yet; never present it as fact), **unverifiable** (no reachable source; say so) or **wrong** (a source contradicts it; correct it and name the source).
- Never write an identifier, version, flag or API from memory: read it from the installed version or the source.
- A network error, rate limit or timeout is not evidence that a source is bad or missing. Report the claim as `unverified` with the reason and retry once when it is cheap.
- Repair only mechanical slips yourself (a mistyped version). Ask when a mismatch could change a decision.

## Evidence, inference, assumption

Label each statement the conclusion rests on: **Evidence** (a quoted source or an observed result), **Inference** (your reasoning from evidence) or **Assumption** (not checked). An uncited inference or an unexamined assumption that carries the conclusion is a risk: check it, or record it with `--add-risk` in a task.

## The scope of a negative

"Not found" means not found in the scanned scope: name what you searched (paths, queries, sources, date). Never write "nothing exists" or "unused" from a bounded search, and never present a sample as the whole population.
