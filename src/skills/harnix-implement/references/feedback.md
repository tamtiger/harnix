# Technical feedback

Feedback from the user or a reviewer is a technical hypothesis, not an instruction to accept blindly.

1. Read the whole message and restate the technical requirement. Clarify ambiguous or coupled items before changing anything.
2. Verify each item against current requirements, code, tests, compatibility and earlier user decisions; classify severity and whether it blocks completion.
3. Apply one item at a time and test it. Batch confirmed blockers into one bounded remediation round.
4. Disagree with evidence, concisely, when feedback conflicts with repository facts or the contract; never accept or reject performatively.
5. Feedback alone never grants permission to edit files outside the task scope, reply on an external system or change Git state.
