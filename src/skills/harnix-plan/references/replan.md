# Replan an unfinished task

Use when checkpoint is `replan`, or obligations must change after `ready`.

1. Obligations (criteria text, checks, their criterion mapping and inputs) freeze at the first persisted `ready`. A revision may only supersede pending, unproven obligations.
2. Make the revision with the flag transports: `harnix workflow --set-check ... --reason <10-1000 characters>` or `--add-criterion ... --check <id> --reason <text>`. Each one is a single guarded save that sets checkpoint `replan` (status unchanged) with a `contractRevision`; Harnix appends the skipped audit evidence `task-contract-revision-NN`. Batch every contract edit into one replan so the reruns happen once.
3. Editing a criterion's text: `harnix workflow --set-criterion <id> --text "<new text>" --reason <why> --brief` (one guarded replan save; free while planning; a Lite task still implementing with no evidence resumes implementing by itself). To waive a criterion instead of rewriting it, send `--batch` with `{ "criteria": [{ "id": "<id>", "status": "waived", "waiverReason": "<why>" }] }` and a `--reason`; a criterion mapped by recorded evidence stays immutable. Never edit `task.json` or the criterion text by hand.
4. Never change a check that has a passing evidence item. Rewriting the text of a criterion whose check recorded evidence is allowed with `--reason` (step 3) and turns those passes stale, so rerun them. A check with only `fail` or `skipped` evidence is retired by keeping its ID and definition unchanged and setting only `required: false`, then adding a new required replacement ID with equivalent criterion coverage. Use `harnix workflow --replace-check <old> <new> --reason <why> [--command --input --cwd ...]` to do both atomically; the replacement must differ from the retired check in `command`, `inputs` or `cwd`. A check that failed twice in a row refuses further evidence until one of three exits: a code change (a new input digest), a user-authorized `harnix workflow --reset-breaker <check-id> --reason <10-1000 characters>`, or a user-authorized `--replace-check` whose `command`, `inputs` or `cwd` differs.
5. Exact replay of the same revision is idempotent.
6. Re-enter the gate: repeat the ready self-review, then `harnix workflow --transition ready/ready` (add `--reviewed` for a Full task). There is no direct backward transition.
7. After a revision every earlier pass is stale (the task contract is folded into every digest). Rerun each required check once with `harnix workflow --run-check <id> -- <exe> [args...]`.
8. When `contextDrift` is `stale`, treat it as a mandatory replan before context reselection; stop if the same drift remains after one reselection in the same request.
