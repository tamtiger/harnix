# Evidence and freshness

- **One command:** `harnix workflow --run-check <id> -- <exe> [args...]` snapshots the check's inputs, runs the executable (no shell), snapshots again and records pass (exit 0) or fail only when the digests are equal. It runs only the declared `command` in the declared `cwd` (a different argv, or `--cwd`, is refused), and new evidence may not be future-dated. Output is returned as `outputTail` and never stored. For a compound command such as `a && b`, declare one check per command or start a shell explicitly (`-- bash -c "a && b"`, full path on Windows). **Prefer `--run-check` for every required check; it records the exact input digest atomically, so a later finish cannot find it stale.**
- **Ordering:** finish re-checks every required digest against current inputs. So record evidence last-to-finish and never run an input-touching command (a build that writes `bin`/`obj`/`dist`, a formatter, a code edit) between recording a check's evidence and `--finish`. When several checks share inputs, run the broadest one (for example a full build) **before** the narrower ones, so an earlier recorded pass is not invalidated by a later run.
- **Manual form:** `harnix workflow --snapshot --check <id>` before and after a non-mutating run; record a pass only when both `inputDigest` values match, with `--evidence --check <id> --result pass --exit-code 0 --summary <text> --digest <before>`. Use the manual form only for a check with no command, or when `--run-check` cannot drive the tool; a hand-recorded pass goes stale the moment any later command rewrites its inputs. An empty glob, missing or unreadable input, or unsafe path is failed freshness evidence, not a warning.
- **Summary shape:** command, then result, then any note.
- **`recordedAt`** comes from the CLI clock; never write your own time.
- **What changes `inputDigest`:** a file matched by the check's `inputs`, or the check's own contract (its own definition, the id and text of the criteria it covers, mode; other checks do not count, and evidence recorded under the former formula stays valid while the whole task contract is unchanged). Not: recording evidence, criterion `status`/`evidenceIds`, ticking `plan.md`, decisions, residual risks. `.git`, `node_modules`, `TestResults`, `.vs`, `.idea`, `__pycache__` and `.harnix` are always skipped (unless an input names that segment); `bin`/`obj` only beside a `.csproj|.fsproj|.vbproj`, and `build`/`dist`/`coverage`/`out` only beside a `package.json|pom.xml|build.gradle*`.
- **Stale reasons:** `digest-mismatch`, `evidence-expired` (legacy v1/v2 records only; a v3 pass never expires by age), `inputs-unavailable`, `latest-failed`, `latest-skipped`, `legacy-schema`, `no-evidence`. `harnix status --explain` lists them without running anything.
- **Convergence:** inspect state once; reuse a matching pass; one automatic remediation round; an identical check/digest/exit/summary fingerprint is the strongest stop signal; skipped or future-dated evidence never resets the breaker, only a current valid pass does. A check that failed twice in a row makes `--run-check` print `stop`: report it, and continue only with a user-authorized `harnix workflow --replace-check <old> <new> --reason <why>` whose `command`, `inputs` or `cwd` differs.
- **Criteria:** link a criterion only to current passing evidence whose check lists it in `criterionIds`.
- **Suppress noise:** do not report readability-only redundancy, requests for comments on thresholds, consistency-only reshaping, harmless no-ops, linter-enforceable style, or anything the diff already fixes.
