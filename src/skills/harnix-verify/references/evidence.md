# Evidence and freshness

- **One command:** `harnix workflow --run-check <id> -- <exe> [args...]` snapshots the inputs, runs only the declared `command` in the declared `cwd`, snapshots again and records pass (exit 0) or fail only when both digests are equal; output comes back as `outputTail` and is never stored (shell and Windows rules: the `cookbook-notes` reference). **Prefer `--run-check` for every required check; it records the exact input digest atomically, so a later finish cannot find it stale.**
- **Ordering:** finish re-checks every required digest against current inputs. So record evidence last-to-finish and never run an input-touching command (a build that writes `bin`/`obj`/`dist`, a formatter, a code edit) between recording a check's evidence and `--finish`. When several checks share inputs, run the broadest one (for example a full build) **before** the narrower ones, so an earlier recorded pass is not invalidated by a later run.
- **Manual form:** `harnix workflow --snapshot --check <id>` before and after a non-mutating run; record a pass only when both `inputDigest` values match, with `--evidence --check <id> --result pass --exit-code 0 --summary <text> --digest <before>`. Use the manual form only for a check with no command, or when `--run-check` cannot drive the tool; a hand-recorded pass goes stale the moment any later command rewrites its inputs. An empty glob, missing or unreadable input, or unsafe path is failed freshness evidence, not a warning.
- **`--exit-code`:** `--exit-code` is required for every `pass` or `fail` that `--evidence` records for a command-backed check (`0` for a pass); `--run-check` fills it.
- **Summary shape:** command, then result, then any note.
- **`recordedAt`** comes from the CLI clock; never write your own time. New evidence may not be future-dated, and a `--cwd` that differs from the check's declared `cwd` is rejected.
- **What changes `inputDigest`:** a file matched by the check's `inputs`, or the check's own contract (its own definition, the id and text of the criteria it covers, mode; other checks do not count, and evidence recorded under the former formula stays valid while the whole task contract is unchanged). Text files are hashed with CRLF read as LF (shell scripts, batch files, Makefiles and Dockerfiles byte for byte), so a checkout with another line-ending setting does not stale a pass; `--snapshot` also returns `rawInputDigest` for evidence recorded from the raw bytes. Not: recording evidence, criterion `status`/`evidenceIds`, ticking `plan.md`, decisions, residual risks. `.git`, `node_modules`, `TestResults`, `.vs`, `.idea`, `__pycache__` and `.harnix` are always skipped (unless an input names that segment); `bin`/`obj` only beside a `.csproj|.fsproj|.vbproj`, and `build`/`dist`/`coverage`/`out` only beside a `package.json|pom.xml|build.gradle*`.
- **Windows line endings:** a diff that shows only CRLF/LF noise is not a change: review with `git diff --ignore-space-at-eol`, and keep line endings stable with a `.gitattributes` rule (for example `* text=auto`); never rewrite a file only to flip its line endings.
- **Stale reasons:** `digest-mismatch`, `evidence-expired` (legacy v1/v2 records only; a v3 pass never expires by age), `inputs-unavailable`, `latest-failed`, `latest-skipped`, `legacy-schema`, `no-evidence`. `harnix status --explain` lists them without running anything.
- **Convergence:** inspect state once and reuse a matching pass; an identical check/digest/exit/summary fingerprint is the strongest stop signal; skipped or future-dated evidence never resets the breaker; only a current valid pass or a user-authorized `--reset-breaker` resets it. A check that failed twice in a row is refused: report it, and continue with a code change (new `inputDigest`), a user-authorized `harnix workflow --reset-breaker <check-id> --reason <why, 10-1000 characters>`, or a user-authorized `--replace-check` whose `command`, `inputs` or `cwd` differs.
- **Criteria:** link a criterion only to current passing evidence whose check lists it in `criterionIds`.
- **Suppress noise:** do not report readability-only redundancy, requests for comments on thresholds, consistency-only reshaping, harmless no-ops, linter-enforceable style, or anything the diff already fixes.
